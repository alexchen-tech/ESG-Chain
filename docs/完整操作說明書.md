## 一、系統簡介

ESG·Chain 是永續供應鏈管理平台，定位為 **ERP 資料之上的永續情報層**，不是 ERP 替代品——供應商、物料、BOM、出口裝運等主檔資料一律由 ERP 匯入（CSV 上傳／Webhook 推送／排程拉取），ESG-Chain 在其上疊加兩條情報線：

- **永續韌性**：SAQ 問卷 → AI 評分 → 風險矩陣 → CAP 矯正行動
- **產品合規**：BOM 碳排 → PCF 計算 → CBAM／EUDR／UFLPA 出口前合規判定

系統功能邊界止於「出口前合規檢查」——實際出口交易執行（客戶/PO 綁定、報關、多批集貨、送件狀態追蹤）屬 ERP 範疇，不在本系統內建置。

三層架構：`esgchain-web`（Vue3 前端，含中心廠介面與供應商 Portal 兩個獨立 build）、`esgchain-api`（Laravel 業務邏輯與狀態機）、`esgchain-ai`（FastAPI 評分/AI 推算引擎）。

建議使用 Chrome/Edge 最新版；畫面採 RWD 設計，手機/平板寬度會自動收合側邊欄為漢堡選單。系統無需安裝任何用戶端軟體，純瀏覽器操作。

登入後左側為分組式側邊欄，依角色顯示可用模組（見「系統權限設定建議」的 RBAC 表）。頂端漢堡按鈕可收合側邊欄節省畫面空間。供應商 Portal 因功能項目較少，改用頂部橫向導覽列，不使用側邊欄。

### 2.4 通用操作慣例
- **重複送出防呆**：所有操作按鈕點擊後立即 disabled 並顯示 loading 狀態，避免重複觸發。
- **列表分頁**：所有列表頁採伺服器端分頁，固定每頁 20 筆。
- **登出**：中心廠側邊欄底部／供應商 Portal 頂部導覽列右側皆有登出按鈕。

## 三、各系統模組操作說明

### 3.1 儀表板（`/dashboard`）
首頁彙總卡片：供應商風險分佈、SAQ 完成率、CAP 待辦數量、近期風險事件。點擊卡片可直接跳轉對應功能頁做進一步處理，避免使用者記路徑。

### 3.2 供應商管理

| 功能 | 路徑 |
|---|---|
| 供應商清單 | `/suppliers` |
| 供應商匯入 | `/suppliers/import` |
| 供應商詳情 | `/suppliers/:id` |
| 供應鏈連結圖 | `/suppliers/network` |

1. **供應商清單**：可依 Tier、風險等級、合作狀態篩選。
2. **供應商匯入**：上傳 CSV → 系統顯示比對預覽 → 確認後寫入。ERP 擁有欄位（code/name/hs_code/status 等）每次同步可覆蓋；ESG-Chain 自有欄位（onboarding_stage/saq_score/risk_level/emission_factor）永不被同步覆蓋。
3. **供應商詳情**：分頁涵蓋基本資料、永續績效（KPI，依領域分組顯示歷年數值）、SAQ 歷史、風險評估（六維雷達圖）、合規文件（含到期預警）、關聯 BOM、設施清單。
4. **合作狀態轉換**：詳情頁點擊「狀態轉換」，選擇 `active/suspended/terminated`，需填寫原因，系統寫入稽核日誌。**注意**：ERP 的 `status`（active/inactive）唯讀不可由此變更，此處變更的是 ESG-Chain 自有的 `onboarding_stage`，兩者語意需保持一致但欄位擁有者不同。
5. **供應鏈連結圖**：視覺化呈現供應商彼此的供應鏈關聯，用於快速掌握供應網路結構。

### 3.3 物料管理

| 功能 | 路徑 |
|---|---|
| 物料主檔 | `/materials/items` |
| 物料群組 | `/materials/groups` |
| 碳排請求 | `/materials/pcf-requests` |

1. **物料主檔**：瀏覽 ERP 同步的料號清單，點入物料詳情頁有三個重點分頁：
   - **碳排資料庫**：同一物料在不同供應商的碳足跡數值由低到高排序，以量級 meter 視覺化比較，統計列顯示最小/平均/最大值——回答「這個物料誰做得最環保」，不是各供應商各自申報一筆看不出比較。
   - **來源供應商分布**：列出這個物料被哪些產品 BOM 行使用、各行目前的主供應商（primary）。若主供應商並非全域最低碳供應商，出現「切換」按鈕，點擊後將該 BOM 行主供應商切換為指定供應商，**該產品的 PCF 會自動重新計算**。
   - **核可供應商**：維護這個物料的核可供應商清單（含製程廠區指定），是產品 BOM 選定實際供應商時的候選來源。
2. **物料群組**：維護物料所屬群組與 `required_doc_types`（決定觸發哪些法規義務文件，如 EUDR_DDS、UFLPA_DECLARATION、CMRT），是整條產品合規流程「這批貨需要哪些文件」的權威定義起點。
3. **碳排請求**：向指定供應商發起特定物料的碳排填報請求，供應商於 Portal「碳排申報」頁回覆。

### 3.4 永續倡議問卷（SAQ）

| 功能 | 路徑 | 可存取 |
|---|---|---|
| 審核管理 | `/questionnaires/review` | admin/sustain/comply/analyst |
| 評核專案 | `/questionnaires/projects` | admin/sustain/comply/analyst |
| 評核系列 | `/questionnaires/series` | admin/sustain/comply/analyst |
| 評核範本 | `/questionnaires/templates` | admin only |
| 題目庫 | `/settings/question-bank` | admin only |

1. **題目庫**：維護題目本體，每題可掛上 L1/L2/L3 三層合規領域標籤（如 `esg.s.forced_labor`），供未來依標籤篩題或客製產業別題組使用。
2. **評核範本**：從題目庫挑題組成一份固定範本，狀態機 `draft→published`；範本一旦被專案使用，之後異動不影響已建立的專案（專案建立時已複製一份題目快照）。
3. **評核系列**：綁定一個範本與一組計分設定（六維權重 `dim_weights`、評等門檻 `grade_thresholds`），確保同系列底下所有專案的分數可以互相比較。系列本身有 `active/archived` 生命週期，跟底下專案的狀態機分開。
4. **評核專案**：在系列下建立，綁定要調查的供應商名單，狀態機 `draft→active→closed`（`closed` 為終態不可逆）。專案頁可對名單內供應商發送問卷。
5. **審核管理**：問卷提交後進入待審清單，審核人員可查看 esgchain-ai 已算好的評分結果（六維分數），決定通過（`completed`，可再標記複核完成 `reviewed`）或退回（`review_returned`，需附退回原因，供應商修改後重新提交會回到 `submitted` 而非直接回 `under_review`，需要審核人員重新按「開始審核」）。

> **狀態機全貌**：`sent`（已發送待填寫）→ `in_progress`（填寫中，存草稿時自動轉入）→ `submitted`（已提交）→ `under_review`（審核中，此狀態下供應商無法讀取/編輯）→ `completed`（審核通過）或 `review_returned`（退回）→ `reviewed`（複核完成，終態）。另有 `disputed`/`re_review`/`finalized` 為申訴流程狀態（供應商可在 `completed` 後 7 天內對評分提出申訴）。

### 3.5 商品合規管理

| 功能 | 路徑 |
|---|---|
| 合規看板 | `/compliance` |
| 銷售產品 | `/sales-products` |
| 生產批號 | `/compliance/production-batches` |
| 出口審查 | `/compliance/export-reviews` |

#### 3.5.1 合規看板
跨產品/供應商總覽：供應商合規總覽、產品 CBAM/EUDR 徽章與 DPP 就緒度、物料群組 × 文件類型合規矩陣、待驗證合規文件清單。這是文件與法規面的彙總入口，跟 SAQ 分數是兩條資料流的匯合（供應商 `risk_score` 只作為矩陣的交叉篩選欄位，不是分析的核心資料源）。

#### 3.5.2 銷售產品
1. 產品清單/匯入，基本資料（名稱/HS Code/型號）由 ERP 同步。
2. 產品詳情頁分頁：
   - **法規適用**：`applicable_regulations`（人工維護的正式清單，ERP 同步永不覆蓋）與 `inferred_regulations`（系統依 BOM 物料群組自動推算，BOM 異動即時觸發重算，不需等排程或開啟儀表板頁面）為兩個獨立欄位，互不覆寫。
   - **BOM 明細**：逐行維護物料、核可供應商清單。
   - **PCF 快照**：歷次 PCF 計算結果，**append-only 不可更新或刪除舊版本**，需要更新時產生新版本快照，舊版本保留供追溯比對。
   - **循環經濟 / 包材 / 電池規格**：依產品類別顯示對應的 DPP 揭露欄位（再生料比例、包材資訊、電池化學系統與關鍵原料含量等，依 EU 電池法規/ESPR 紡織品最小揭露欄位規範建置）。

#### 3.5.3 生產批號
1. 批號清單由 ERP 同步或手動建立，含批次 PCF。
2. 批號詳情頁四個分頁：批號資訊、碳足跡與循環經濟（含 ISO 14067 就緒度缺口原因逐項列出）、有害物質揭露、**供應鏈合規**。
3. 「供應鏈合規」分頁涵蓋：
   - **供應鏈製程級地點**：批次涉及的製程類型（染整/成衣製造等，由 BOM 涉及核可供應商 `facility_type` 聯集決定），逐項選定實際執行的供應商/廠區，已選定的旁邊會顯示該供應商既有 SAQ 六維風險評分徽章（環境管理/社會責任構面，唯讀資訊，不影響出口審查關卡判定）。
   - **原物料合規與溯源管理**：逐 BOM 物料填寫這批貨**實際**使用的供應商與產地（GPS、收穫年份、認證編號），這是出口審查的合規判定依據，優先於產品層級的理論核可清單。

#### 3.5.4 出口審查
1. 清單頁跨批號彙總，可依市場/狀態/生產日期篩選，「未審查」狀態批號一律列出不會因無資料被排除；篩定市場後可用「一鍵審查本頁未審查批號」批次執行。
2. 展開任一批號的操作面板：選市場＋法規範疇（DPP/CBAM/EUDR/UFLPA，留空為完整審查）→「執行審查」；若該市場已有審查結果會提示是否覆蓋（重跑不保留歷史）。
3. 審查結果逐項列出檢核項目與 pass/warning/fail，未通過項目附「前往補件」連結直接跳轉到對應供應商合規文件分頁或批號詳情頁補齊溯源，不需要重新走一次建檔流程。
4. **批次護照（Batch Passport）**：點擊可產生單一批次的完整唯讀 JSON 彙總（產品身分/碳足跡/循環經濟/合規文件/原料溯源/製程盡職調查/出口審查歷史），支援複製 JSON。
5. **出口合規文件草稿（DDS）**：即時查詢產生，不落地保存版本，正式送件文件請另行處理。

> **系統邊界提醒**：本頁只做出口前合規判定與文件草稿產出，實際出口交易執行（客戶/PO 綁定、報關、送件狀態追蹤）屬 ERP 範疇，不在本系統內。

### 3.6 風險稽核

| 功能 | 路徑 |
|---|---|
| 永續風險概覽 | `/risk` |
| 地緣事件複查 | `/risk/geo-events` |
| 出口合規風險看板 | `/trade-goods/export-risk` |
| CAP 矯正 | `/cap` |

1. **永續風險概覽**：六維風險熱圖（E1 環境管理／E2 氣候與碳排／E3 社會責任／E4 地緣風險／E5 公司治理／E6 供應鏈透明度），可依供應商/國別/Tier 篩選；原獨立的「風險矩陣」頁面已整合進本頁（`/risk/matrix` 會自動導向 `/risk`）。
2. **地緣事件複查**：檢視地緣政治風險事件（區域衝突、貿易制裁等）及其對供應商組合的潛在影響評估。
3. **出口合規風險看板**：商品 × 市場路徑風險熱力圖，支援「商品優先」/「市場優先」樞紐視角切換；點擊儲存格展開義務缺口明細（法規義務、負責供應商、文件狀態）；對缺件供應商可查詢替換供應商建議（融合 ESG 風險與實測碳排評分，附「僅供決策輔助、實際換源需透過 ERP」的免責提醒）。
4. **CAP 矯正**：風險評估自動觸發（六維分數低於門檻）或人工建立的矯正任務清單，追蹤至結案；供應商於 Portal 端更新進度並上傳佐證附件，指派時系統會寄送 email 通知。

### 3.8 供應商 Portal（獨立 build，僅 supplier/sup_esg 登入）

| 功能 | 路徑 |
|---|---|
| 供應商入口首頁 | `/supplier/portal` |
| 合規文件 | `/supplier/compliance` |
| 採購需求 | `/supplier/portal/procurement` |
| 碳排申報 | `/supplier/portal/pcf` |
| 永續 KPI 填報 | `/supplier/portal/disclosures` |
| 活動資料申報 | `/supplier/portal/activity-reports` |
| CAP 矯正 | `/supplier/portal/caps` |
| 供應商主檔 | `/supplier/profile` |
| 問卷填寫 | `/supplier/survey/:id` |

1. **供應商入口首頁**：待填問卷（SAQ）表格（含「已退回」狀態的醒目提示與退回說明入口）、待填碳排（PCF）任務、活動資料申報提醒，是整個 Portal 的操作總樞紐，其餘頁面完成任務後多半會導回這裡。
2. **合規文件**：三個分頁——上傳合規文件（UFLPA/EUDR DDS/CMRT 等，含發證/到期日）、貿易商品碳排回報、物料碳排提報。
3. **採購需求**：檢視買方（中心廠）發出的物料指定與所需合規文件，供應商端唯讀，產品資訊匿名顯示。
4. **碳排申報**：針對被要求的 BOM 物料填報碳足跡數值。
5. **永續 KPI 填報**：依領域分組（溫室氣體排放/能源使用/勞動權益/水資源/廢棄物/公司治理/多元共融/供應鏈管理/職業安全/認證資格）填報年度指標，支援數值/布林/單選三種欄位型態；若某年度數值已由問卷同步（`source=saq_sync`），手動修改會標記為手動填報並提示已覆蓋問卷數值。
6. **活動資料申報**：逐設施填報季度用電/天然氣/燃料油/外購熱能/用水量等活動資料，供範疇一/二溫室氣體排放計算使用。
7. **CAP 矯正**：查看被指派的矯正項目、更新進度、上傳佐證附件。
8. **問卷填寫**：逐題作答，可存草稿分次完成，提交後不可再編輯直到審核結果出爐（退回才能再編輯）。

## 四、功能流程摘要

完整互動架構圖另行發布，本節僅列文字摘要。

**SAQ 問卷生命週期**：題目庫→評核範本→評核系列→評核專案→發送→供應商填寫提交→AI 非同步評分回填六維分數→中心廠審核（通過/退回）→風險評估自動衍生→低於門檻自動建立 CAP。

**產品合規調查（建檔到出口）**：物料群組設定合規要求→建立產品與 BOM→核可供應商→系統即時推算適用法規→供應商上傳合規文件→建立生產批號→填寫實際原料溯源→選定製程實際供應商→執行出口市場審查→未通過補件重跑。

**供應商加入與狀態管理**：ERP 匯入或手動建立→中心廠執行狀態轉換（`onboarding_stage`，需填原因並留稽核日誌）→ ERP `status` 欄位唯讀僅供參考。

**CAP 矯正行動**：風險評估自動觸發或人工建立→指派供應商並寄送通知→供應商更新進度、上傳附件→中心廠追蹤結案。

**合規文件到期追蹤**：文件依 `expires_at` 自動計算狀態（pending/valid/expiring_soon/expired）→合規看板與供應商詳情頁彙總顯示→到期前主動聯繫或於出口審查時系統自動標示並附補件連結。

## 五、各角色腳本範例

### 5.1 管理員（admin）—— 系統設定與全模組稽核
1. 登入 → 儀表板確認整體風險/CAP待辦概況
2. 「系統設定 → 市場合規規則」新增一條 EU 市場、UFLPA 文件的合規規則
3. 「永續倡議問卷 → 題目庫」新增一題並標記 `esg.s.forced_labor` 標籤
4. 「供應商管理」點入任一供應商，執行狀態轉換測試（active → suspended，填寫原因）
5. 「風險稽核 → CAP 矯正」查看目前所有待結案項目

### 5.2 採購商（buyer）—— 商品建檔與出口審查
1. 登入 →「商品合規管理 → 銷售產品」新增一筆銷售產品，填 HS Code
2. 新增 BOM 明細，逐行關聯物料並選定核可供應商
3. 「生產批號」為此產品建立一筆批號
4. 批號詳情頁「供應鏈合規」分頁，填寫原料溯源與製程供應商選定
5. 「出口審查」對此批號選 EU 市場＋DPP 範疇，執行審查
6. 未通過項目點擊「前往補件」補齊，回出口審查頁重跑

### 5.3 永續長（sustain）—— SAQ 專案發起與審核
1. 登入 →「永續倡議問卷 → 評核系列」建立新系列，設定六維權重
2. 「評核專案」在此系列下建立專案，選擇要調查的供應商名單並發送問卷
3. 供應商提交後，「審核管理」開始審核，查看 AI 評分結果，決定通過或退回
4. 通過後「風險稽核 → 永續風險概覽」確認該供應商六維分數已更新

### 5.4 法遵（comply）—— 合規文件與出口把關
1. 登入 →「商品合規管理 → 合規看板」查看待驗證文件清單
2. 供應商詳情頁「合規文件」分頁，對供應商上傳的文件執行驗證
3. 「出口審查」篩選「未審查」狀態、指定市場，使用「一鍵審查本頁未審查批號」
4. 檢視「未通過」項目，確認是否需要開立 CAP

### 5.5 分析師（analyst）—— 風險監控與報表
1. 登入 →「風險稽核 → 永續風險概覽」檢視六維風險熱圖，篩選高風險供應商
2. 「永續倡議問卷 → 審核管理」查看目前各狀態問卷分佈
3. 供應商詳情頁查看個別供應商的歷年 SAQ 分數趨勢與永續績效 KPI 分組資料

### 5.6 供應商（supplier）—— 問卷填寫與文件維護
1. 登入供應商 Portal → 首頁「待填問卷」點擊「填寫」，逐題作答並提交
2. 「合規文件」分頁上傳一份 UFLPA 聲明（填發證日期/到期日）
3. 「碳排申報」查看待填 PCF 請求並回覆數值
4. 「活動資料申報」為所屬設施填寫本季用電/用水數據並提交

### 5.7 供應商 ESG 窗口（sup_esg）—— 永續資料維護與矯正追蹤
1. 登入供應商 Portal →「永續 KPI 填報」逐項填寫年度 KPI 數值
2. 「CAP 矯正」查看被指派的矯正項目，更新進度並上傳佐證附件
3. 「合規文件」的「碳排回報」分頁，為所屬產品回報碳排數值
4. 收到問卷「已退回」通知，找到該問卷依退回說明修改後重新提交

## 六、系統權限設定建議

### 6.1 現況：前端選單過濾 vs 後端實際落實程度

| 邊界 | 落實方式 | 落實程度 |
|---|---|---|
| 供應商（supplier/sup_esg）vs 中心廠 | 後端 middleware（路由白名單）＋ 前端獨立 build | **已落實**：供應商 JWT 直接打中心廠 API 會被後端拒絕，不只是前端擋 |
| 中心廠內部角色（admin/buyer/sustain/comply/analyst）之間 | 僅前端側邊欄選單過濾 | **未落實**：後端 API 目前沒有依內部角色做細緻的模組級存取控制，五種角色之一登入理論上都能直接呼叫任何中心廠 API |

供應商邊界（外部、不受信任來源）已完成後端強制修復；內部角色邊界目前僅靠前端選單「不顯示」，本質是信任內部員工假設下的權宜設計。

### 6.2 建議

1. **優先級**：內部角色間的模組級權限矩陣是否需要補到後端，取決於實際治理需求。若合規/稽核要求需要留下「誰能做什麼」的強制紀錄而非僅靠自律，建議下一階段為 admin/buyer/sustain/comply/analyst 建立對應的後端角色中介層。
2. **高風險操作優先補強**：建議優先為「供應商狀態轉換」「CAP 建立/結案」「市場合規規則設定」「題目庫/評核範本編輯」這類具稽核/合規意義的寫入操作加上後端角色檢查。
3. **測試帳號與正式環境隔離**：`demo1234` 密碼僅供測試環境使用，正式上線前務必更換強密碼並停用示範帳號。
4. **供應商 Portal 網路層隔離（可選的下一步強化）**：後端授權與前端拆分已完成，若要進一步降低攻擊面，可考慮中心廠介面收進 VPN/IP 白名單，供應商 Portal 維持公開但加速率限制與 MFA。
5. **CORS 設定隨部署環境調整**：目前設定為本機開發環境，正式上線需改為實際網域，避免萬用字元。
6. **定期複查白名單/門檻設定**：路由白名單、CAP 觸發門檻、市場合規規則皆為手動維護，建議新功能上線前納入檢查清單。

## 八、常見問題（FAQ）

**Q：供應商的名稱/HS Code 改不了？**
A：這些欄位由 ERP 擁有，每次同步會覆蓋，UI 上不開放編輯屬正常設計，需回 ERP 端修改後等待同步。

**Q：出口審查的市場文件規則要去哪裡改？**
A：「系統設定 → 市場合規規則」（admin 專用）。

**Q：PCF 快照算錯了，可以修改嗎？**
A：PCF 快照為 append-only，不可修改或刪除舊版本；重新計算會產生新版本快照，舊版本仍保留供追溯比對。

**Q：供應商填的問卷被退回了，怎麼找不到？**
A：退回的問卷仍留在供應商 Portal 首頁「待填問卷」清單裡，狀態標示「已退回」，點擊「查看退回說明」即可進入修改。

**Q：登入畫面顯示「請至供應商 Portal 登入」是什麼意思？**
A：代表這個帳號是供應商角色，登錯了中心廠介面入口，請改用供應商 Portal 網址登入。

**Q：出口審查一直顯示「可能已過期」是什麼？**
A：代表審查完成之後，該批次相關供應商的合規文件又有更新，建議重新執行一次審查以取得最新判定。

**Q：供應鏈製程級地點卡片顯示「待選定」？**
A：代表這個製程類型還沒有人為這批貨指定實際供應商，只是列出理論上的候選名單，需要手動選定才會影響出口審查判定。
