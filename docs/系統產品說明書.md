# ESG·Chain 系統產品說明書

版本：v1.0　最後更新：2026-07-16

---

## 一、系統概述

**ESG·Chain** 是永創數智開發的永續供應鏈管理平台，提供品牌採購商、永續團隊、法遵部門訂閱使用，並提供供應商入口（Portal）讓上游廠商填寫問卷與碳排填報。

系統核心任務是把離散的供應鏈永續資訊——供應商自評問卷、物料碳足跡、BOM 結構、出口市場法規——整合成一條可追溯、可比較、可稽核的情報鏈，最終產出 CSRD 永續報告、產品碳足跡（PCF）報告、CBAM 申報、EUDR 盡職調查聲明等法遵文件。

### 目標使用者

| 角色 | 使用情境 |
|---|---|
| 品牌採購商（buyer） | 管理供應商名單、BOM 與 SKU、生產批號出口前合規檢查 |
| 永續團隊（sustain） | 追蹤 SAQ 評核、風險矩陣、CAP 矯正行動 |
| 法遵部門（comply） | 商品合規檢核、出口市場法規審查、文件到期管理 |
| 分析師（analyst） | 檢視儀表板、風險趨勢、報表 |
| 供應商 / 供應商 ESG 窗口（supplier / sup_esg） | 透過 Portal 填答問卷、申報物料碳排、上傳合規文件 |

## 二、系統邊界：ERP 資料之上的永續情報層

**ESG-Chain 不是 ERP 替代品**，而是建立在 ERP 主檔資料之上的永續情報層：

```text
ERP（唯一主檔來源）
  供應商 / 物料 / BOM / 出口裝運
      ↓  CSV 上傳 | Webhook 推送 | 排程拉取
ESG-Chain（加入永續情報）
  ├─ 永續韌性：SAQ 問卷 → AI 評分 → 風險矩陣 → CAP 矯正行動
  └─ 產品合規：BOM 碳排 → PCF 計算 → CBAM / EUDR / UFLPA 申報
      ↓
輸出：CSRD / PCF 報告 / CBAM 申報 / EUDR DDS / 批次護照 API
```

### 欄位歸屬原則

系統嚴格劃分「誰是資料的主人」，ERP 同步時不得覆蓋 ESG-Chain 自行計算或人工確認的欄位：

| 擁有者 | 實體 | 欄位範例 | Sync 行為 |
|---|---|---|---|
| **ERP** | Supplier | code, name, hs_code, supplier_code, status, tier | 每次同步可覆蓋 |
| **ERP** | SalesProduct（銷售產品，原 TradeGood/BuyerProduct 已合併） | name, product_code, hs_code, quantity | 每次同步可覆蓋 |
| **ESG-Chain** | Supplier | onboarding_stage, saq_score, risk_level, impact_score, spend_amount | 永不被 sync 覆蓋 |
| **ESG-Chain** | SalesProduct | applicable_regulations, inferred_regulations, embedded_emissions | 永不被 sync 覆蓋 |

供應商合作狀態機（ESG-Chain 擁有，與 ERP `status` 語意對齊但獨立管理）：

```text
active ──→ suspended ──→ terminated
             └──→ active
```

## 三、系統架構

三層式微服務架構，各司其職：

| 服務 | 技術 | 職責 | Port |
|---|---|---|---|
| **esgchain-web** | Vue 3 + Vite + Pinia + TypeScript | 前端 SPA | 5173 |
| **esgchain-api** | Laravel 12 / PHP 8.5 + MySQL 8.4 | 業務流程、狀態機、CRUD、ERP 對接 | 8081 |
| **esgchain-ai** | FastAPI / Python 3.12 + PostgreSQL + Celery + Redis | 評分引擎、PCF 計算、AI 推算、非同步任務 | 8000 |

- **Nginx** 統一入口：`/api` → Laravel、`/ai` → FastAPI、`/` → Vue 3
- **JWT 分工**：esgchain-api 負責 RS256 金鑰發行與換發；esgchain-ai 只驗證、不發行
- **資料庫分工**：MySQL 存業務資料（Supplier / SAQ / CAP / BOM / ProductionBatch）；PostgreSQL 存計算相關資料（EmissionFactor / ScoringModel / RiskAssessment）

## 四、功能模組總覽

### 4.1 供應商管理
供應商主檔、匯入（CSV/ERP）、合作狀態機轉換（active/suspended/terminated）、合規文件庫、供應商群組。

### 4.2 物料管理
- **物料主檔**：ERP 同步的料號基本資料，可掛物料群組（決定該物料觸發哪些法規義務文件，如 UFLPA_DECLARATION、EUDR_DDS、SDS）
- **碳排資料庫**：同一物料跨供應商碳足跡比較——依碳排值排序、標示最低/最高、視覺化相對量級 meter，可一鍵**切換主供應商**（改用更低碳的核准供應商），觸發該產品 PCF 自動重算
- **碳排請求（PCF Requests）**：向供應商發起特定物料的碳排填報請求

### 4.3 永續倡議問卷（SAQ）
- **評核範本 / 評核系列 / 評核專案**：多框架問卷範本管理，支援依 SASB 產業別配置必調題目與權重
- **審核管理**：供應商填答後的人工複核、爭議處理
- SAQ 完成後**自動推導**六維風險評估（AI 評分服務）

### 4.4 商品合規管理
- **合規看板**：跨產品的法規適用（CBAM/EUDR）與上游文件齊備度總覽
- **銷售產品（SalesProduct）**：唯一產品主檔（整合原 TradeGood 與已廢棄的 BuyerProduct），含 BOM 明細、法規適用判定（CBAM 自動判定、EUDR/UFLPA 依 BOM 物料群組推算）、PCF 快照、碳排回報
- **BOM 管理**：ERP 匯入為主，記錄各行物料的核准供應商名單（AVL），支援 Tier1–Tier4 完整供應鏈追溯，禁止循環參照
- **生產批號**：ERP 同步的實際生產批次，含批次 PCF、原料溯源（GPS 地塊座標、收穫年、認證編號，供 EUDR DDS / UFLPA 佐證）
- **出口市場審查**：批號 × 目標市場的合規審查引擎，逐項檢核市場文件規則、EUDR 溯源完整性、UFLPA 棉花溯源、批次 PCF、DPP 欄位完備度，產出 pass/warning/fail 結論
- **出口合規文件產出**：單一生產批號可直接產出該批×市場的合規文件草稿（如 EUDR DDS），內含商品資訊、批次 PCF、原料溯源與當下審查結論。系統邊界止於「出口前合規檢查」——實際出口交易執行（客戶/PO 綁定、報關、多批集貨、送件狀態追蹤）屬 ERP 範疇，不在本系統內建置

### 4.5 風險稽核
- **永續風險概覽（六維熱圖）**：E1 環境管理／E2 氣候與碳排／E3 社會責任／E4 地緣風險／E5 公司治理／E6 供應鏈透明度
- **風險矩陣（5×5）**：Probability × Impact 矩陣，Impact 採四因子加權計分（Tier、採購額、單一來源依賴、材料關鍵性），取代早期單純依賴 Tier 的粗略判定
- **地緣事件複查**：地緣政治風險事件對供應商組合的影響評估
- **CAP 矯正行動**：風險評估/SAQ 低分自動生成矯正任務，追蹤關閉

### 4.6 出口合規風險看板與供應商替換推薦
商品 × 市場路徑風險熱力圖，點擊儲存格展開「義務缺口明細」（該商品在此市場的法規義務與負責供應商文件狀態），可對缺件供應商發起「換供應商」查詢，候選評分融合 ESG 六維分數與**實測物料碳排**（而非僅供應商自評的氣候治理分數）。

### 4.7 供應商入口（Portal）
供應商角色專屬視圖：問卷填答、合規文件上傳、碳排申報（含既有 BOM 匹配狀態）、永續 KPI 揭露填報、採購需求檢視。

### 4.8 系統設定
一般設定、分類與計分管理（六維權重、SASB 產業必調題目）、客戶主檔、市場合規規則（依市場/文件類型設定強制或建議、生效日期、物料層或產品層適用範圍）。

## 五、核心資料流程

### 流程一：永續韌性鏈
```
SAQ 問卷填答 → AI 評分（六維） → 風險評估寫入 → 風險矩陣（P×I）→ 低分自動生成 CAP → 矯正追蹤關閉
```

### 流程二：產品合規鏈
```
ERP 匯入 BOM（Tier1–4 供應鏈）→ 物料碳排比較/選定供應商 → PCF 計算 → 法規適用判定（CBAM/EUDR/UFLPA）
  → 生產批號 + 原料溯源 → 出口市場審查（pass/warning/fail）→ 產出合規文件草稿（EUDR DDS）
      ↓（系統邊界，以下由 ERP 執行）
  客戶/PO 綁定 → 多批集貨 → 報關送件 → 實際出口
```

### 流程三：供應商優化鏈
```
物料碳排比較發現更低碳供應商 → 一鍵切換 BOM 主供應商 → PCF 自動重算
  或
義務缺口面板發現文件缺失 → 換供應商推薦（ESG + 實測碳排融合評分）→ 候選詳情 → 採購流程執行
```

## 六、法規覆蓋範圍

| 市場 | 涵蓋法規 | 判定方式 |
|---|---|---|
| EU | EUDR（零毀林）、CBAM（碳邊境調整）、REACH（化學品）、原產地證明、DPP（數位產品護照，2027 前瞻規則） | HS 碼（CBAM）+ 物料群組推算（EUDR/REACH）|
| US | UFLPA（強迫勞動預防）、CMRT（衝突礦產）、原產地證明、CPSIA（童裝安全，建議級）、Prop 65（建議級） | 物料群組推算 + 供應商層文件 |
| UK | 原產地證明、UK REACH、Modern Slavery Act 聲明 | 同上 |
| JP | 原產地證明、甲醛限量檢測、家庭用品品質表示 | 同上 |

物料層規則依 BOM 物料群組的 `required_doc_types` 自動觸發；產品層規則（如 DPP、CPSIA）於該市場一律適用，不受個別物料影響。

## 八、對外整合

- **ERP 同步**：CSV 上傳／Webhook 推送／排程拉取三種模式，欄位歸屬嚴格區分（見第二節）
- **批次護照 API**：`GET /api/v1/export/batch-package/{批號}`，X-Api-Key 認證，供 DPP 平台或報關系統以生產批號拉取完整追溯資料包（產品識別、供應鏈、原料溯源、出口市場審查結論）
- **AI 服務內部端點**：SAQ 計分、六維計分、PCF 計算、地緣風險推算、供應商替換候選路徑風險模擬，皆由 esgchain-api 呼叫，計算邏輯集中於 esgchain-ai，不落地在業務層
